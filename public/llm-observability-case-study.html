01 — The brief

A RAG system you can actually debug.

A RAG pipeline has three places latency and quality can quietly degrade: retrieval, reranking, and generation. I built the tracing and dashboarding layer that makes each stage visible instead of guessed at.

02 — The problem

Debugging a RAG pipeline blind.

Attribution

Which stage is slow?

A single end-to-end latency number doesn't say whether retrieval, reranking, or generation caused a slowdown.

Cost

Token spend was invisible

Without per-query cost tracking, a prompt or model change could quietly inflate spend before anyone noticed.

Regression

Quality drops shipped silently

Nothing stopped a change that degraded answer quality from reaching production before a human noticed.

03 — The approach

How a query gets observed.

01
Stage

End-to-end tracing

What it does

Langfuse instruments every request, breaking it into retrieval, reranking, and generation spans with their own timing.

02

Metrics export

What it does

Prometheus scrapes latency, cost, and quality metrics from the FastAPI service on every request.

03

Dashboards

What it does

Grafana dashboards track p50/p95 latency, token cost per query, and quality scores over time, broken down by pipeline stage.

04

Regression gate

What it does

A GitHub Actions check blocks a deploy automatically when latency spikes or an evaluation score drops below threshold.

04 — Results

What became visible.

3 stages
Retrieval, reranking, and generation each traced and timed separately.
p50 / p95
Latency percentiles tracked continuously on Grafana, not just averages.
Per-query
Token cost tracked at the individual query level, not just in aggregate.
Auto-blocked
CI gating stops a deploy when latency or quality regresses — no manual check required.
05 — Under the hood

The engineering decisions.

LangfusePrometheusGrafanaPythonFastAPIGitHub Actions
Tracing

Span-level, not request-level.

Langfuse spans wrap each pipeline stage individually, so a latency spike can be attributed to retrieval versus generation instead of guessed at.

Dashboards

One place for latency, cost, and quality.

Grafana panels pull from the same Prometheus metrics store, so latency percentiles, token cost, and quality scores live side by side.

CI gating

The pipeline fails closed.

A GitHub Actions job runs the evaluation suite on every change; a regression in latency or quality score fails the check instead of shipping silently.

Serving

Instrumented at the FastAPI layer.

Metrics are emitted directly from the serving layer, so the dashboards reflect real production traffic, not a synthetic sample.

06 — Honest scope

What this layer doesn't do yet.

No alerting yet

Dashboards surface regressions visually; there's no paging or Slack alert wired up for on-call response.

Single-service scope

Tracing covers the RAG service itself, not every upstream or downstream dependency in the broader system.

Fixed evaluation thresholds

The CI quality gate uses static thresholds rather than statistical drift detection.

Next steps

Where this goes next.

Alerting

Wire Grafana alert rules into Slack or PagerDuty for real-time incident response.

Drift detection

Replace static thresholds with statistical drift detection on quality scores over time.
