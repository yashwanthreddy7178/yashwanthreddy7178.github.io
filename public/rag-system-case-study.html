01 — The brief

Financial answers, verified before they're trusted.

Financial documents are long, dense, and full of numbers that matter. I built a retrieval system that finds the right passage and lets analysts verify the answer against the source, instead of trusting a model's memory.

02 — The problem

Where plain search and plain LLMs both fall short.

Neither keyword search nor a bare LLM call was good enough on its own.

Recall

Keyword search misses paraphrase

Pure BM25 misses relevant passages that use different wording for the same concept — common in financial filings written by different authors.

Precision

Vector search returns near-misses

Semantic search alone often surfaces passages that are topically close but not the specific figure or clause being asked about.

Trust

Ungrounded answers hallucinate

Without citation enforcement, an LLM will confidently state a number it never actually read — expensive to get wrong in a financial context.

03 — The approach

How a query becomes a verified answer.

A hybrid pipeline, in the order a query actually moves through it.

01
Stage

Hybrid retrieval

What it does

BM25 keyword search runs alongside FAISS vector search, so the system catches both exact terminology and paraphrased meaning.

02
Stage

Cohere reranking

What it does

Candidates from both retrievers are reranked by relevance to the specific query, pushing the true best passage to the top.

03
Stage

Citation enforcement

What it does

The model is required to ground every answer in a retrieved passage it can cite, cutting hallucinated figures out of the response.

04
Stage

Quality gate

What it does

A Ragas evaluation pipeline scores answer quality on every change and blocks a deploy if the score regresses.

05
Stage

Serving

What it does

FastAPI serves the pipeline, tested through GitHub Actions on every change before it ships.

05 — Under the hood

The engineering decisions.

PythonLangChainFAISSBM25Cohere RerankFastAPIRagasGitHub Actions
Retrieval

Two retrievers, one ranked list.

BM25 and FAISS run in parallel over the same corpus; their candidates are merged and passed to a Cohere reranker before the top passages reach the model.

Evaluation

Ragas as a CI gate, not an afterthought.

Every pull request runs the pipeline against a held-out question set. A regression in faithfulness or answer relevance blocks the merge.

Latency

Sub-2-second answers on long documents.

Chunking and index structure are tuned so a 500+ page document still resolves a query in under 2 seconds end-to-end.

Grounding

Citations aren't optional.

The generation step is constrained to quote or reference the retrieved passage it draws from, which is what drove the 40% drop in hallucinated content.

06 — Honest scope

What this system doesn't do yet.

Single-document-set tuned

Retrieval parameters are tuned against the financial-document corpus it was built for and would need re-tuning for a different domain.

No multi-hop reasoning yet

The pipeline answers from a single best passage; questions that require combining facts across multiple documents aren't handled.

Ragas set is held-out, not live

The evaluation question set is fixed at build time — it doesn't yet learn from real user queries in production.

Next steps

Where this goes next.

Multi-hop

Add query decomposition so questions spanning multiple documents can be answered.

Live eval set

Fold real, anonymized production queries back into the Ragas evaluation set over time.
