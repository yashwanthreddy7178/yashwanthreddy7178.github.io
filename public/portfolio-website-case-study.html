01 — The brief

A portfolio that shows the work, not just lists it.

Most portfolio sites are a grid of cards linking to dead demos. I wanted each project to open into an actual case study — the problem, the approach, the honest limitations — with the site itself built to the same standard.

02 — The problem

What a project-card grid leaves out.

Depth

A card can't explain a decision

A two-line description can't carry why a concurrency model was redesigned or what a metric actually measures.

Trust

Dead demo links erode credibility

A "Demo" button that goes nowhere is worse than no button — it reads as unfinished rather than in-progress.

Consistency

Every project looked different

Without a shared template, each write-up would drift in tone and structure, making the whole portfolio feel disjointed.

How the site is put together.

Case-study template

04 — Under the hood

The engineering decisions.

Next.jsTypeScriptTailwind CSSFramer Motion
Framework

Next.js App Router.

The site runs on Next.js with TypeScript throughout, keeping component props and data shapes checked at build time.

Motion

Animation that respects intent.

Framer Motion drives scroll-triggered reveals and hover states, wrapped so prefers-reduced-motion is respected.

05 — Honest scope

What this site doesn't do yet.

Static project images

Several project cards still use placeholder imagery rather than real screenshots.

No CMS

Content is authored directly in components rather than pulled from a headless CMS, so updates require a code change.

Next steps

Where this goes next.

Real screenshots

Replace remaining placeholder images with actual product screenshots.

Content layer

Move project copy into a structured data source so new projects don't require editing components directly.
