02 — The approach

What I built.

A React single-page application covering the full shopping path, with a purple accent replacing the original monochrome.

Routes

Home → Product

Persistent header, category row, and a full-screen hero replace the single-product landing.

Routes

Search → Wishlist

A dedicated search route with live suggestions and a seven-control filter panel.

Routes

Cart → Auth

Cart, login, and signup share an AuthContext that gates account features.

03 — Before / After

One storefront, two philosophies.

Before · zara.com
  • Menu hidden behind a faint hamburger icon
  • Centered wordmark, no visible actions
  • One oversized image, faint low-contrast text
  • No sort, filter buried in a corner
  • No visible reviews on product pages
After · redesign
  • Fixed header: search, wishlist, account, cart always visible
  • High-contrast purple CTAs read as buttons at a glance
  • Full-screen hero with one headline, one action
  • Dedicated search page, 7-control filter panel
  • Rating summary, review list, and a working review form

05 — Honest scope

What this prototype does not do yet.

A portfolio piece earns trust through candor.

Front end only

Product data, prices, and order totals use hardcoded sample values. There is no backend or product API.

Demo authentication

Login checks one hardcoded account and stores state in memory — no real auth or persistence.

No usability testing

The redesign responds to documented critiques but carries no measured usability results of its own.

Baseline scores

Run Lighthouse and an axe/WAVE scan against a measured zara.com baseline.

Real data layer

Wire a product API, persistent cart, and token-based auth to replace sample values.
